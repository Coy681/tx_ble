# Memory Management Unit

该模块定义了协议栈所需要的一些内存管理方式，共计三种，分别是
- ml - malloc（动态内存分配）
- bl - block list（块链表）
- rb - ring buffer（环形缓冲区）

## malloc

做嵌入式开发的工程师们大多数都听过一句话：嵌入式领域资源紧张，malloc 这种内存管理方式耗费资源大、执行效率低、容易产生内存碎片，所以要尽可能避免使用 malloc。不知道各位有没有对这个观点做出深刻的思考和实验。

我想强调的一点是：没有不合适的技术，只有不会用的技术。一项技术的使用者必须对这项技术有深刻的了解和完整的认知，才能发挥其最大优势。在我看来，malloc 在嵌入式领域利用得当，不仅可以大幅提高开发速度，还能有效提升系统的资源利用效率。malloc 单独使用当然会有上述资源效率的诸多缺点，但 malloc 结合一些简单的内存管理方式（如 block list/ring buffer），可以有效规避这些问题。

针对大家对 malloc 的刻板印象（即其固有的缺点），我设计了一套改进的 malloc/free 操作函数，主要优化如下：

**(1)** 高效的内存链式管理
        采用简洁的链式结构管理内存块，每块内存仅额外占用 12 字节（用于元数据，如块大小、前后指针等），大幅提升内存利用率
**(2)** 轻量化的操作逻辑
        简化 malloc 和 free 的核心逻辑，减少冗余判断和计算。实测显示，单次 malloc 或 free 操作的执行时间可控制在 10μs 以内，满足多数嵌入式场景的实时性需求。
**(3)** 自动碎片回收机制
        释放内存时，会自动检测并合并相邻的空闲块，从根源上减少内存碎片的累积，避免 “有内存但无法分配” 的问题。

通过上述关键改动，malloc操作处理函数具有高效/低耗的特点，一定程度上改善了传统malloc机制所存在的缺点

## block list

块链表是一种基于预分配的内存管理方式，核心思想是 “一次申请、多次复用”，适用于需要频繁分配固定大小内存块的场景（如协议栈中的数据包缓冲区）。

核心特点：

- 固定块大小：用户可指定单个块的大小（size）和总块数（n），初始化时通过 malloc 一次性申请一块连续的大内存，并将其拆分为 n 个大小为 size 的小内存块。
- 双链表管理：分为空闲链表和非空链表，所有空闲块通过空闲链表串起来，所有非空闲块通过非空链表串起来(可配置升序或者降序)，用户申请节点时从空闲链表申请节点，插入到非空链表中去，用户释放节点时从非空链表pop节点，插入到空闲链表。
- 零碎片风险：由于块大小固定，分配和释放不会产生内存碎片，适合长期运行的嵌入式系统。

## ring buffer

环形缓冲区是一种基于数组的循环内存管理方式，适用于 “生产者 - 消费者” 模型（如数据收发、日志缓存），核心优势是高效的顺序读写和固定内存占用。

核心特点：

- 循环复用：采用数组实现，通过头尾指针（head/tail）标记数据的起始和结束位置，数据读取后内存可自动复用，无需频繁释放。
- 固定大小：初始化时指定缓冲区总大小（size），内存一次性分配，运行中无动态内存操作，避免碎片和不确定性。
- 高效读写：读写操作仅涉及指针移动和边界判断，时间复杂度为 O (1)，适合高频率数据传输场景（如 UART 数据缓存、DMA 缓冲区）。
- 线程安全：配合简单的锁机制（如信号量），可在多任务环境下安全使用，避免数据竞争

# 组合使用建议

在实际开发中，三种方式可结合使用以发挥最大优势：

- 用 malloc 初始化 block list 和 ring buffer 的底层内存，避免直接操作裸 malloc。
- 高频、固定大小的内存需求（如数据包），有序数据处理用 block list。流式数据缓存（如串口数据）用 ring buffer。
- 临时的、大小不固定的内存需求（如配置解析）用改进后的 malloc，配合及时释放和碎片回收机制。

通过合理搭配，可在保证系统稳定性和实时性的同时，兼顾开发效率和资源利用率。
